# Moody: implementation plan, M3 (playlists + listening history) ✅ (2026-10-31)

Spec: [`../specs/2026-09-28-moody-rewrite-design.md`](../specs/2026-09-28-moody-rewrite-design.md), §8–§11.

**Goal:**
- Build mood-path playlists ("Distress → Relaxation in 20 tracks") on the map and take them elsewhere: an M3U file for Apple Music or VLC, or a Spotify playlist.
- Join Last.fm and Spotify listening history to the analyzed library to show the mood of what you actually play.

**One change to the spec:** the path planner runs in the browser (TypeScript) instead of behind `POST /api/playlists/path`.
- Paths re-plan while you drag them, and they work in the static Pages demo too.
- The only new data is a 32-dim style vector per track.

**Verification:**
- **Backend:** 194 pytest tests, ruff, mypy `--strict`. Spotify and Last.fm run against in-memory fakes via httpx2 `MockTransport`, so CI makes no network calls.
- **Mutation checks:** for the planner, the Spotify safety and matching rules, Last.fm paging order, the dedupe window and Spotify's timing, I broke each rule on purpose and confirmed a test fails.
- **Frontend:** 71 vitest tests, eslint, `tsc`.
- **End-to-end:** 11 Playwright specs, 5 of them new for the path builder (3 repeats locally).
- **Real browser, real server:** the path page, saving, the M3U download (absolute paths), audio with Range, the Connect Spotify redirect (PKCE parameters checked) and the History page in light and dark.
- **Planner speed:** about 20–50 ms for a 600-track library in the test runner; about 190 ms for 100k tracks at length 50.

**Exit test (the author's Mac):**
1. Run `git pull`, then `uv run moody scan …` (applies migrations 0004–0006).
2. Run `npm run build`, then `uv run moody serve --ui ../frontend/dist`.
3. Build "Distress → Relaxation, 20 tracks", play it, save it, and import the M3U into Apple Music.
4. Set `MOODY_SPOTIFY_CLIENT_ID` and export the playlist to Spotify.
5. Set `MOODY_LASTFM_API_KEY` and run `uv run moody history lastfm <user>`, then open `#/history`.

**Known limits carried forward:**
- Only plays of analyzed songs have a mood. With the 2007 thesis library scanned, overlap with today's listening may be small; every import reports it.
- Apple Music's privacy export (Play Activity CSV) is not imported yet. Its columns have changed over the years, so it needs a real sample.
- `POST /api/scan`, jobs and SSE progress moved to M4. The CLI covers scanning, and imports report their own progress.
- Spotify Development Mode allows 5 users and needs the app owner on Premium.
