# Moody: implementation plan, M4 (showcase)

Spec: [`../specs/2026-09-28-moody-rewrite-design.md`](../specs/2026-09-28-moody-rewrite-design.md), §10–§12, §15.

**Goal:** make Moody presentable to people who won't install it:
- a public demo on GitHub Pages with real, analyzed, CC-licensed music
- an honest evaluation report
- a README with GIFs
- the deferred "scan from the web app"

**Decisions (2026-10-31):**
- Demo music comes from the MTG-Jamendo mood/theme split-0 **test** set, CC BY / CC BY-SA only, through the Jamendo API.
- The analysis runs in GitHub Actions.
- Pages deploys on `v*` tags or manually.

**Verification so far:**
- **Backend:** 211 pytest tests, ruff, mypy `--strict`. Jamendo is faked with `MockTransport`, covering lookups, licences, retries, resumable downloads and shard merging.
- **Frontend:** 80 vitest tests. End-to-end: 13 Playwright specs, run against a fixture now built like a demo bundle (credits, stream URLs).
- **Real browser:**
  - scan from the app: SSE progress, then the map refreshes
  - demo audio and credits
  - clip recording
- **Two CI-only failures found and fixed:**
  - Rich colours Typer's errors under GitHub Actions, which broke a substring check.
  - A test left a background scan running past app shutdown, which surfaced as a ResourceWarning. Reproduced locally in 2 of 5 runs; 8 of 8 pass after the fix.
- **Two UI bugs found while recording:**
  - dragging a handle selected text
  - (from M3) the handle hit area

**Remaining steps (need the Jamendo client id):**
1. Add the repository secret `JAMENDO_CLIENT_ID`.
2. Run **Demo bundle** (Actions → Demo bundle → Run workflow). It takes about 1–2 hours and publishes `demo-bundle-…` plus `eval/tags-moodtheme`.
3. Merge the tag results into `eval/results/` and run `eval/render.py`.
4. Run **Pages** (or push a `v0.4.0` tag) for the public demo at https://circuitflow.github.io/moody/.
5. Run **README media** and merge `readme-media` for the GIFs.
